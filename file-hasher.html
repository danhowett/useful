Using the hasher

Drop files or folders anywhere on the page, or use Choose files / Choose folder. Tick the algorithms you need in the sidebar — ticking another one later hashes the files already listed for that algorithm too. Click any hash to copy it.

⤓
Exporting. Export CSV saves every listed file with the ticked algorithms as columns, plus size, last-modified and hashed-at times in UTC, and the case reference if you set one. Hash list copies hash␠␠path lines for the first ticked algorithm, compatible with sha256sum -c and similar.
Checking a known hash
  • Paste an MD5, SHA-1, SHA-256, SHA-384 or SHA-512 value into the sidebar search. A banner says whether any listed file matches, and matching rows are highlighted.
  • Files with identical content are flagged DUP; click the flag to show the set.
Things to know
  • Paths are relative to the folder you dropped or chose. Browsers do not expose full on-disk paths.
  • Last modified is the time your OS reports to the browser. It is a convenience field, not a forensic timestamp — use your filesystem tooling for MACB times.
  • CSV safety: any cell starting with = + - @ is prefixed with an apostrophe so spreadsheet apps cannot run it as a formula. Hostile filenames are common in evidence sets.
  • SHA hashes on files up to 128 MB use the browser's built-in crypto; larger files and all MD5 work are streamed in 8 MB chunks, so very large images are fine but slower than a native tool.
  • This is a triage and verification aid. For evidential acquisition, record hashes from your validated imaging tool.

Runs entirely in your browser. Nothing is uploaded; only your theme and algorithm choices are remembered.
